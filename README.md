## نصب و منوی مدیریت

نصب را روی همان سروری انجام دهید که پنل روی آن نصب شده است. به Python 3، Bash و curl نیاز دارید؛ مدیریت سرویس‌ها برای Linux با systemd در نظر گرفته شده است. اگر روی Ubuntu/Debian این ابزارها نصب نیستند:

```bash
apt update
apt install -y ca-certificates curl python3
```

سپس از طریق SSH با کاربر root وارد سرور پنل شوید.

با همان دستور قبلی، با کاربر root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YASIN0ASADI/ghost-sub/main/install.sh)
```

نصاب فایل‌های کامل نسخهٔ فعلی را دریافت و منوی مدیریت را باز می‌کند. ورود به منو به‌تنهایی قالب یا سرویس پنل را restart نمی‌کند؛ عملیات را از منو انتخاب می‌کنید. دفعه‌های بعد برای بازکردن منوی نصب‌شده:

```bash
ghost-sub
```

| گزینه | کار |
|---|---|
| ۱ | نصب یا اعمال نسخهٔ قالب موجود در بسته |
| ۲ | تغییر برند، لوگو و رنگ با همان نصاب |
| ۳ | پیکربندی تاریخچهٔ اختیاری ثنایی |
| ۴ | پیکربندی مانیتور سرورها با مقصدهای ثابت |
| ۵ | بررسی محلی و فقط خواندنی |
| ۶ | بازگردانی بکاپ مشخص همان پنل |

نصب ظاهر قبل از جایگزینی قالب بکاپ خصوصی می‌گیرد و پس از تأیید، پنل انتخاب‌شده را restart می‌کند؛ برای کاربران فعال زمان مناسب انتخاب کنید.

برای دریافت به‌روزرسانی، همان دستور تک‌خطی را دوباره اجرا کنید؛ سپس گزینهٔ نصب/اعمال قالب را انتخاب کنید. تنظیمات ذخیره‌شده با Enter حفظ می‌شوند.

## راهنمای گام‌به‌گام ظاهر و عکس پروفایل

۱. دستور تک‌خطی نصب را اجرا کنید و در منو گزینهٔ۱ برای نصب، یا گزینهٔ۲ برای تغییر ظاهر را انتخاب کنید.

۲. نوع پنل را انتخاب کنید: `1` ثنایی، `2` پاسارگارد، `3` مرزبان. سپس نام برند و رنگ پیش‌فرض را بدهید. رنگ‌ها: `1` قرمز، `2` سبز، `3` آبی. در نصب بعدی Enter تنظیمات ذخیره‌شده را حفظ می‌کند؛ در اولین ارتقا از قالب قدیمی نام برند را دوباره وارد کنید.

۳. در سؤال `Image address or choice` می‌توانید مستقیماً مسیر فایل **روی سرور** یا لینک HTTPS عکس را بدهید:

```text
/root/ghost-profile.jpg
```

یا لینک مستقیم HTTPS که خود تصویر را برمی‌گرداند؛ لینک صفحهٔ اشتراک عکس یا صفحهٔ HTML قابل استفاده نیست. همچنین `1` برای Ghost، `2` برای پرسیدن آدرس عکس و `3` برای حذف نشان قابل انتخاب است. Enter لوگوی ذخیره‌شده را حفظ می‌کند؛ در نصب اولیه Ghost پیش‌فرض است.

۴. برای عکس شخصی، قاب را انتخاب کنید: `1` گرد، `2` مربع با گوشه‌های گرد. تصویر جای Ghost در بالای صفحه قرار می‌گیرد. عکس درون HTML جاسازی می‌شود و مسیر asset عمومی جدید لازم نیست. PNG، JPG/JPEG و WebP تا ۲۵۶ کیبی‌بایت و عرض/ارتفاع حداکثر ۲۰۴۸ پیکسل پذیرفته می‌شوند. عوض‌کردن پسوند، فرمت عکس را تبدیل نمی‌کند؛ محتوای فایل بررسی می‌شود. تصاویر مربعی و بدون حاشیه برای قاب پروفایل مناسب‌ترند.

### انتقال عکس از ویندوز به سرور

مسیر ویندوز مانند `C:\Users\...` روی سرور لینوکسی وجود ندارد. ابتدا فایل را با SCP منتقل کنید. دستورهای این قسمت در **PowerShell ویندوز** اجرا می‌شوند.

برای دیدن نام دقیق عکس‌ها در پوشهٔ Telegram Desktop:

```powershell
Get-ChildItem "$env:USERPROFILE\Downloads\Telegram Desktop" -File |
    Where-Object { $_.Extension -in '.jpg','.jpeg','.png','.webp' } |
    Select-Object Name, Length
```

نام کامل فایل را در دستور زیر جایگزین کنید؛ `SERVER_IP` هم آدرس سرور پنل است. گیومه‌ها برای مسیر دارای فاصله لازم‌اند:

```powershell
scp "$env:USERPROFILE\Downloads\Telegram Desktop\photo.jpg" root@SERVER_IP:/root/ghost-profile.jpg
```

اگر پورت SSH مثلاً ۲۲۲۲ است، حرف بزرگ `P` را اضافه کنید:

```powershell
scp -P 2222 "$env:USERPROFILE\Downloads\Telegram Desktop\photo.jpg" root@SERVER_IP:/root/ghost-profile.jpg
```

می‌توانید به‌جای تایپ نام فایل، پنجرهٔ انتخاب عکس باز کنید و پسوند اصلی را حفظ کنید:

```powershell
Add-Type -AssemblyName System.Windows.Forms
$picture = New-Object System.Windows.Forms.OpenFileDialog
$picture.Filter = "Profile image|*.jpg;*.jpeg;*.png;*.webp"
if ($picture.ShowDialog() -eq [System.Windows.Forms.DialogResult]::OK) {
    $remoteImage = "/root/ghost-profile" + [IO.Path]::GetExtension($picture.FileName).ToLowerInvariant()
    scp "$($picture.FileName)" "root@SERVER_IP:$remoteImage"
    if ($LASTEXITCODE -eq 0) { Write-Host "Image path for installer: $remoteImage" }
}
```

پس از انتقال، در **ترمینال سرور** وجود فایل را بررسی کنید:

```bash
ls -lh /root/ghost-profile.jpg
```

سپس همان مسیر `/root/ghost-profile.jpg` را در سؤال عکس نصاب بدهید. اگر فایل PNG یا WebP انتخاب کرده‌اید، پسوند مسیر را هم مطابق خروجی انتقال وارد کنید.

### سؤال‌های بعد از عکس

| سؤال نصاب | معنی | اگر این قابلیت را تنظیم نکرده‌اید |
|---|---|---|
| `Status feed` | مسیر یا URL دادهٔ مانیتور دسترسی سرورها؛ آدرس عکس نیست | Enter؛ بدون feed، وضعیت نامشخص می‌ماند |
| `History route` در ثنایی | مسیر همان‌مبدأ خروجی سرویس تاریخچه، مانند `/ghost-usage/` | Enter؛ نمودار تاریخچهٔ جدید غیرفعال می‌ماند |
| `Install and restart selected panel?` | تأیید جایگزینی قالب و restart پنل انتخاب‌شده | برای ادامه `y`؛ برای انصراف Enter |

Enter در تنظیمات اختیاری، مقدار ذخیره‌شدهٔ قبلی را نگه می‌دارد؛ برای حذف مقدار قبلی `off` وارد کنید. نصب عکس نیازمند راه‌اندازی هیچ‌کدام از این دو سرویس اختیاری نیست.

### خطاهای متداول عکس و انتقال

| پیام | علت و اقدام |
|---|---|
| `is not a regular file` | مسیر یک پوشه است؛ نام کامل فایل عکس را هم بعد از پوشه بنویسید. برای عکس از `scp -r` استفاده نکنید. |
| `No such file or directory` | نام/مسیر اشتباه است؛ با `Get-ChildItem` در ویندوز یا `ls` در سرور بررسی کنید. |
| `Connection closed` | اتصال SSH بسته شده؛ پورت، دسترسی SSH و پیام کامل اتصال را بررسی کنید. این پیام به‌تنهایی مشکل عکس یا پسوند را ثابت نمی‌کند. |
| `Permission denied` در SSH | نام کاربر، رمز/کلید و مجوز ورود را بررسی کنید. |
| `Logo file not found on this server` | عکس هنوز روی سرور نیست یا مسیر ویندوز وارد شده است. |
| پیام محدودیت حجم/ابعاد | عکس را به حداکثر ۲۵۶ کیبی‌بایت و ۲۰۴۸ پیکسل کاهش دهید. |

## تغییر ظاهر و به‌روزرسانی بعدی

برای تغییر عکس/برند روی همان نسخه `ghost-sub` را اجرا کنید و گزینهٔ۲ را بزنید. برای گرفتن کد جدید، دستور تک‌خطی نصب را دوباره اجرا کنید تا منو و فایل‌ها تازه شوند؛ سپس نصب/اعمال قالب را انتخاب کنید. فقط بازکردن منوی نصب‌شده کد جدید را از GitHub دریافت نمی‌کند. بعد از ذخیره، صفحهٔ ساب را بدون کش باز کنید یا در ویندوز Ctrl+F5 بزنید.

## نمودارها و سرویس‌های اختیاری

| بخش | منبع داده | راهنما |
|---|---|---|
| مصرف فعلی | مقادیر خود پنل در قالب | نیازمند فعال‌بودن صفحهٔ ساب پنل |
| تاریخچهٔ Marzban/Pasarguard | Tracker قبلی یا fallback موجود مرورگر | جریان نصب قبلی حفظ شده است |
| تاریخچهٔ 3X-UI | collector جدا با دسترسی API سمت سرور | [راهنمای ثنایی](docs/3XUI_HISTORY_FA.md) |
| نمودار دسترسی سرورها | نمونه‌برداری TCP از سرور مانیتور | [راهنمای مانیتور](docs/STATUS_MONITOR_FA.md) |

نصب قالب به‌تنهایی پایش یا تاریخچه را فعال نمی‌کند. برای سرویس‌های جدید، پیکربندی، start و فعال‌سازی هنگام بوت انتخاب‌های جدا هستند؛ ارائهٔ داده از مسیر HTTPS هم‌مبدأ نیازمند تنظیم reverse proxy است.

وضعیت TCP سلامت کامل کانفیگ یا آپ‌تایم سیستم‌عامل را اثبات نمی‌کند. بدون دادهٔ تازه، وضعیت نامشخص است. تاریخچهٔ ثنایی دادهٔ پیش از نصب را بازسازی نمی‌کند و جایگزین آمار صورتحساب پنل نیست. رمز یا API token پنل را داخل HTML، مخزن یا تصویر قرار ندهید.

## فعال‌سازی قالب در پنل

### 3X-UI

در تنظیمات Subscription، مسیر Sub Theme Directory را روی این پوشه قرار دهید:

```text
/etc/3x-ui/sub_templates/my-theme/
```

### Marzban و Pasarguard

طبق روش نصب پنل، این تنظیمات را در فایل env آن قرار دهید:

```dotenv
CUSTOM_TEMPLATES_DIRECTORY="/var/lib/marzban/templates/"
SUBSCRIPTION_PAGE_TEMPLATE="subscription/index.html"
```

برای Pasarguard مسیر پایه را به `/var/lib/pasarguard/templates/` تغییر دهید و گزینهٔ غیرفعال‌کردن Subscription Template را خاموش کنید. مسیر mount در نصب‌های Docker باید با تنظیمات پنل مطابقت داشته باشد.

## بکاپ و بازگردانی

قالب و manifest قبلی در `/root/ghost-sub-backup.*` ذخیره می‌شوند؛ داخل پوشهٔ عمومی ساب قرار نمی‌گیرند. گزینهٔ۶ منو بکاپ‌های جدید دارای مشخصات همان پنل را بازمی‌گرداند و از وضعیت فعلی هم نسخهٔ بازیابی می‌گیرد. بکاپ‌های قدیمی بدون مشخصات، بررسی دستی می‌خواهند. این قابلیت بازگردانی کل سیستم، دیتابیس یا تنظیمات سرویس‌ها نیست.
