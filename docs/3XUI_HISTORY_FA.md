# تاریخچهٔ مصرف ثنایی و منوی مدیریت — candidate

این نسخه رابط اختیاری تاریخچه برای sub.html دارد. مصرف فعلی صفحه همچنان از uploadByte/downloadByte پنل می‌آید؛ نمودار جدید فقط دادهٔ ثبت‌شده پس از شروع collector را نشان می‌دهد.

## دامنهٔ سازگاری

دو ساختار API پوشش داده شده‌اند،نه تضمین تمام نسخه‌ها/فورک‌ها:

| رابط | روش خواندن | تأیید فعلی |
|---|---|---|
| مدل کلاینت جدید | /panel/api/clients/list ؛ traffic.up/down | fixture و سرور HTTP محلی ساختگی |
| مدل قدیمی inbounds | /panel/api/inbounds/list ؛ clientStats و settings.clients | fixture و سرور HTTP محلی ساختگی |
| یک پنل واقعی کاربر | حالت v3، یک ساب | جمع‌آوری موفق گزارش شد؛ تعمیم به همهٔ نسخه‌ها نمی‌شود |
| فورک/ساختار ناشناخته | تاریخچه unavailable ؛ قالب اصلی باقی می‌ماند | رفتار خطا آزموده شده |

مبنای ساختار مستندات رسمی بررسی‌شده در ۸ نوامبر ۲۰۲۶ است:
https://docs.sanaei.dev/docs/reference/api/clients/
https://docs.sanaei.dev/docs/reference/api/inbounds/

API mode می‌تواند auto/v2/v3 باشد. auto در اولین موفقیت روش را تشخیص و در state خصوصی ثابت می‌کند؛ خطای موقت،شبکه یا permission باعث جابه‌جایی روش شمارش نمی‌شود. پس از ارتقای بنیادی پنل،تغییر mode باید انتخابی و با بررسی baseline باشد.

## تنظیم از منو

پس از نصب بستهٔ کامل،منو با این فرمان باز می‌شود:

```bash
sudo ghost-sub
```

اگر فقط می‌خواهید ابتدا منو را نصب کنید و هنوز قالب/سرویس را تغییر ندهید،از پوشهٔ کامل بسته:

```bash
sudo python3 -I scripts/install_manager.py
```

نصب منو فقط فایل‌های برنامه و launcher را می‌نویسد؛حساب،تنظیمات خصوصی یا سرویس تازه نمی‌سازد و چیزی start/enable نمی‌کند.

گزینهٔ۳ پیکربندی collector ثنایی را می‌گیرد. آدرس پنل باید basepath سفارشی را هم داشته باشد. ورود با token سمت سرور یا session username/password انجام می‌شود؛رمز/token با getpass خوانده و در /etc/ghost-history/config.json خصوصی ذخیره می‌شود،نه HTML و نه argv. برای نسخهٔ دارای scoped token از مجوز خواندن موردنیاز استفاده کنید. ورود 2FA/session ممکن است نیازمند API token مناسب باشد؛خاموش‌کردن 2FA لازم یاپیشنهاد نشده است.
TLS اعتبارسنجی می‌شود؛ HTTP فقط با IP لوپ‌بک مجاز است. CA خصوصی را می‌توان با ca_file معرفی کرد؛ verify خاموش نمی‌شود. redirect احراز هویت دنبال نمی‌شود.
نصب collector و start و boot سه انتخاب روشن و جدا هستند. config قبلی درنصب دوباره حفظ می‌شود.

## اتصال خودکار به لینک اصلی — گزینهٔ۸

برای صفحهٔ ساب HTTP، گزینهٔ۸ مسیر تاریخچهٔ توکن همان ساب را از سرویس دادهٔ همان سرور فعال می‌کند. آدرس صفحه، توکن، عکس و نمودار دسترسی حفظ می‌شوند. API credential به مرورگر نمی‌رود؛ دادهٔ JSON فقط تاریخچهٔ همان توکن را دارد. پورت داده باید قابل دسترس باشد و CORS فقط برای Origin اصلی تنظیم‌شده صادر می‌شود. رمز/توکن API داخل HTML قرار نمی‌گیرد. انتقال HTTP خود لینک ساب رمزگذاری‌شده نیست؛ این ویژگی HTTP را به HTTPS تبدیل نمی‌کند.

اگر collector فعال و نمونه‌برداری موفق است، گزینهٔ۸ را مستقیم بزنید؛ لازم نیست گزینهٔ۳ را تکرار کنید. جزئیات نصب/رفع خطا در README آمده است. برای ورود HTTPS، روش دستی reverse proxy بخش بعد یک جایگزین است و نصب خودکار HTTP روی صفحهٔ HTTPS اعمال نمی‌شود.

## ارائهٔ تاریخچه فقط به صاحب همان اشتراک

سرویس فقط روی 127.0.0.1:19192 گوش می‌دهد. مسیر /history/SUBSCRIPTION_TOKEN تنها همان اشتراک را می‌خواند؛لیست کاربرها،نام‌ها،توکن API و UUID را برنمی‌گرداند.
شناسهٔ subscription نقش کلید دسترسی همان لینک اشتراک را دارد؛باید تصادفی و محرمانه بماند. شناسه‌های ۸ تا ۱۲۸ کاراکتری حرف/عدد/-/_ پشتیبانی می‌شوند؛لینک‌های فرمت دیگر فعلاً تاریخچه ندارند.

نمونهٔ route در HTTPS origin همان صفحهٔ ساب:

```nginx
location /ghost-usage/ {
    access_log off;
    proxy_pass http://127.0.0.1:19192/history/;
    proxy_set_header Host localhost;
    add_header Cache-Control "no-store" always;
    add_header Referrer-Policy "no-referrer" always;
}
```

اینقطعهپیکربندیکامل proxy نیست. اگر proxy داخل container است آدرس loopback متفاوتاست؛مسیرواقعی بررسیشود. route هایپنل راتغییرندهید. پورت collector عمومینشود و DB/config در webroot قرارنگیرند.
درنصابظاهری 3X-UI ، History route را /ghost-usage/ واردکنید. در مسیر دستی URL خارجی پذیرفته نمی‌شود؛ تنها حالت خودکار گزینهٔ۸ اجازهٔ پورت مشخص روی همان hostname صفحهٔ HTTP را می‌دهد. Enter مقدار قبلی را نگه می‌دارد؛ off غیرفعال می‌کند.
وجودفایلکنارقالب کافی نیست؛باید route واقعی HTTP تنظیم شود. تست chroot/file یا API ساختگی جایاینمرحله را نمی‌گیرد.

## نحوهٔ محاسبه

- نمونهٔاول baseline است؛مصرف قبل ازنصب بهروزهایگذشته نسبت داده نمی‌شود.
- نمودار ازاختلافشمارنده‌ها ساخته می‌شود. تاریخچهٔ usage جدید synthetic monotonic است وبلغ charge/ماندهٔصورتحساب نیست.
- resetCounter یاافت counter وقفه‌دارعلامت می‌خورد؛مصرف منفی ساخته نمی‌شود. مصرفی کهقبل از reset و بین دونمونه اتفاقافتاده ممکن است قابل‌بازیابی نباشد.
- تغییرشناسه/نسلکلاینت وقطع طولانی ثبت، baseline تازه و gap دارند؛جهش ساختگی ثبت نمی‌شود.
- همان traffic record تکراری درچند inbound دوبارهجمعنمی‌شود. رکوردهایمتفاوتدرهمان subscription جمع می‌شوند؛تغییرنام/شناسه پیچیده رویپنلواقعی باید بررسیشود.
- بافهرستموفقجدید،اشتراکحذف‌شده دسترسی تاریخچه را ازدست می‌دهد. درقطع API پسازمهلت freshness ،داده قدیمیارائه نمی‌شود.
- نمودارمرتبطباسهمیهٔکنونی،مقدارباقی‌مانده یا OS uptime نیست؛کارتاصلیپنل منبعآنعددهاست.

## منوی مدیریت

۱. اعمالنسخهٔهمراهقالب؛پیشازانتشار،دانلود main نسخهٔجدیدرانمی‌آورد.
۲. تغییرظاهر ازهماننصاب،باپیش‌فرض‌هایذخیره‌شده.
۳. تنظیم collector ثنایی؛ Tracker قبلی Marzban/Pasarguard دست‌نخورده است.
۴. تنظیمپایشگرثابتسرورها؛شروع/boot انتخابجدا.
۵. بررسیفایل‌ها،وضعیتسرویس‌ها،اعتبار config وعمردادهٔآخر؛بدون probe یا restart خودکار. route/browser health جداگانه بایدتست شود.
۶. بازگردانیبکاپقالبهمانپنل؛فقطبکاپجدیددارای panel.json قابلانتخاباست. بکاپقدیمیبدونشناسه adopt نمی‌شود. قبل restore بکاپنجاتگرفتهوشروعمجددپنلخودکارانجامنمی‌شود.

گزینه‌های۱و۲ طبقنصابپسازتأییدممکن استپنلانتخاب‌شده را restart کنند. ورودبه‌منوهیچکاریخودکارانجامنمی‌دهد. تغییراتنیازمند root وترمینالواقعی‌اند.
بازگشتمنو فقط index.html/manifest همانپنلاست؛نسخهٔبرنامهٔ manager ، DB یا credentialcollector را rollback نمی‌کند.

## بررسی‌های انجام‌شده

۱۸تستمنطق/API/reset/privacy ،ورودکوکیواقعیبهپنل HTTP محلیساختگیبا basepath ،هردو adapter وثبتانتخابدر SQLite پاسشدند. نصب staged منو، mode فایل‌ها وورود/خروجبدوناثر آزمودهشدند. رویهیچپنلواقعییاسرورکاربرنصب نشده؛سازگاریباهمهٔنسخه‌هاادعانمی‌شود.
