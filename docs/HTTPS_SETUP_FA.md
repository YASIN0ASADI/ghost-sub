# اتصال نمودار به ساب HTTPS با حفظ لینک

این تغییر پس از انتشار روی GitHub از همان دستور نصب معمول دریافت می‌شود. فعلاً کد و تست آماده شده‌اند؛ تست زنده روی سرور کاربر HTTPS هنوز گزارش نشده است.

## پیش‌نیاز

- خود ساب با https:// و گواهی معتبر باز شود.
- فایل fullchain و کلید متناظر روی همین سرور موجود باشند؛ مسیر را از تنظیمات SSL پنل یا ابزار گواهی بردارید.
- گواهی برای همان hostname یا IP لینک ساب و حداقل تا ۲۴ ساعت بعد معتبر باشد. گواهی عمومی قابل اعتماد لازم است؛ خودامضا یا گواهی origin-only جایگزین نیست.
- پورت داده جدید از سمت مرورگر روی همان میزبان قابل دسترس باشد. پورت ساب عوض نمی‌شود. اگر CDN پورت را عبور نمی‌دهد، مسیر HTTPS روی reverse proxy موجود لازم است.

## بعد از دریافت نسخه جدید

۱. دستور نصب تک‌خطی README را اجرا کنید تا کد manager تازه دریافت شود.
۲. اگر قالب فعلی قدیمی است، گزینه ۱ را بزنید و تنظیمات ذخیره‌شده را با Enter نگه دارید.
۳. مانیتور را از گزینه ۴ تنظیم/شروع کنید. لینک کامل نمونهٔ ساب، شامل شناسهٔ کاربر، باید https:// باشد.
۴. گزینه ۷ را انتخاب کنید؛ همان پنل و یک پورت داده آزاد را مشخص کنید.
۵. مسیر fullchain.pem و privkey.pem را روی سرور بدهید. این مسیرها لینک اینترنتی یا مسیر ویندوز نیستند. فایل کلید را برای کسی نفرستید.
۶. نصاب تطبیق گواهی، کلید، اعتبار زمانی و میزبان را بررسی می‌کند. پس از تأیید نصب، یک نسخه خصوصی برای سرویس داده ساخته می‌شود؛ تنظیمات وب‌سرور یا دیتابیس پنل و لینک اصلی تغییر نمی‌کنند. پنل انتخاب‌شده برای بارگذاری قالب briefly restart می‌شود.
۷. همان لینک اصلی ساب را با تازه‌سازی بدون کش باز کنید.
۸. برای نمودار مصرف 3X-UI، collector را از گزینه ۳ فعال و سپس گزینه ۸ را اجرا کنید. گزینه ۸ از همان سرویس داده HTTPS استفاده می‌کند.

مسیر داخلی monitor روی 19191 و collector روی 19192 همچنان loopback است و نباید عمومی شود. پورت انتخابی داده، تنها JSON وضعیت و مسیر مصرف هر توکن را ارائه می‌کند. Cookie و اطلاعات ورود پنل به آن ارسال نمی‌شوند.

## تمدید گواهی

نسخه سرویس داده از فایل‌ها کپی می‌شود. بعد از تمدید گواهی اصلی، گزینه ۷ را دوباره اجرا و مسیر fullchain و key اصلیِ تمدیدشده را وارد کنید. نگه‌داشتن مسیر کپی قبلی با Enter گواهی تازه را پیدا نمی‌کند. hook تمدید خودکار در این نسخه نداریم. نسخه‌های قبلی گواهی در پوشه‌های خصوصی باقی می‌مانند تا rollback تنظیمات قبلی به فایل حذف‌شده اشاره نکند.

## خطاها

- خطای TLS قبل از تأیید: مسیر، کلید متناظر، دامنه/IP و انقضا را بررسی کنید؛ تنظیمات هنوز عوض نشده‌اند.
- خطای آماده‌سازی بعد از restart: اعتماد CA سیستم، fullchain کامل، وضعیت ghost-status و دسترسی UID سرویس به نسخه کپی‌شده را بررسی کنید. قالب قبلی برگردانده می‌شود و بکاپ خصوصی چاپ می‌شود. اعتبارسنجی را خاموش نکنید.
- محلی سالم ولی مرورگر خطا می‌دهد: پورت عمومی، CDN، گواهی قابل اعتماد در مرورگر، CORS origin و connect-src در CSP موجود را بررسی کنید. نصاب آن سیاست‌ها را خودکار بازنویسی نمی‌کند.

تست‌های توسعه شامل TLS واقعی با گواهی آزمایشی، رد نام/اعتماد اشتباه، مسیر مصرف و CORS، رد HTTP روی پورت TLS، ادامه پاسخ در حضور یک handshake کند و مجوز فایل‌های خصوصی است. تست زنده عمومی یا همه نسخه‌های پنل ادعا نمی‌شود.
